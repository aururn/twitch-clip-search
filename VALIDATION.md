# Verification — 2026-10-18 JST

- Version 1.4.1 streams verified Twitch batches into IndexedDB and the UI before the full page finishes verification. Partial batches keep the original page cursor, so cancellation preserves verified clips and leaves the page resumable. Candidate-page caching retains only IDs and titles for up to 24 pages, with a five-minute TTL and persistence across panel restarts. Fresh repeated searches use local matches without restarting collection. Date, view-count and grapheme formatters are reused during rendering.
- Live `mondo` first-page baseline: 200 source candidates, 65 matching titles; source response 3,090ms, full verification 2,252ms, first publication 5,343ms. After streaming, first verified publication took 3,465ms and complete-page verification took 5,409ms. Reusing that page and verified metadata took 1ms with zero additional source or Twitch requests. These are individual network samples and module-processing measurements, not guarantees of UI latency or faster exhaustive search. The cold source response still dominates the first publication.
- All 34 deterministic tests and the existing browser fixtures passed after the performance change, including progressive verified publication, cancellation before the page checkpoint advances, persistent cache reuse, expiry, explicit cache clearing, and retained title filtering.
- The actual extension's live browser check displayed its first `mondo` result in 3,836ms and retained 326 matching titles after the timed collection. Repeating the same search made zero additional source or Twitch requests and completed the test observation in 146ms (including a deliberate 100ms no-network observation). No page errors were reported.
